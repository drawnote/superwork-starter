# 코딩 에이전트와 함께 할 때

Claude Code 같은 코딩 에이전트를 써도 좋습니다. 단, 이 숙제의 목적은 **여러분이 모델링을 결정하는 것**입니다.
에이전트가 답을 먼저 써 버리면 배울 것이 없습니다. 아래 프롬프트로 시작하세요.

## 시작 프롬프트 (복사해서 사용)

```text
나는 이 저장소에서 내 업무 하나를 Superwork World(superwork.world/v1)로 모델링하는 숙제를 하고 있어.
AGENTS.md의 규칙을 따라줘.

도와줄 것:
- 실제 업무 하나(Work Type)와 그것을 둘러싼 최소한의 World를 모델링하는 것을 도와줘.
- 최종 답을 바로 쓰지 마. 먼저 나에게 물어서 내가 직접 정하게 해줘:
  - Entity (무엇이 존재하고 추적되는가)
  - State (주인공 Entity가 거치는 상태)
  - Transition (무엇이 상태를 바꾸고, 누가 할 수 있는가)
  - Constraint (무엇이 절대 허용되면 안 되는가)
- 한 개념을 여러 방식으로 모델링할 수 있으면(예: 승인을 State / Transition / Entity 중 무엇으로),
  대안을 보여주고 내가 고르게 한 뒤, 그 이유를 assignment/modeling-decisions.md에 기록하게 해줘.
- world.yaml을 바꿀 때마다 npm run validate 를 실행하고 결과를 보여줘.
- 정상 시나리오 하나와 공격 시나리오 하나를 scenarios/에 쓰는 것을 도와줘.
  판정(ALLOW/DENY)은 내가 먼저 예측하게 하고, world.yaml의 상태 · 역할 · guard로 함께 확인해줘.
- 설계 빈틈을 찾으면 프롬프트가 아니라 world.yaml의 규칙으로 고치고, 같은 시나리오를 다시 판정해줘.
```

## 좋은 사용법

- 에이전트에게 **질문을 시키세요**: "내 업무 설명에서 Entity 후보가 될 만한 것을 물어봐줘."
- 에이전트의 제안은 **후보**입니다. `entity-decisions.md`에 여러분의 최종 분류와 이유를 쓰세요.
- 판정 예측은 먼저 여러분이 하세요. 틀려도 괜찮습니다 — 리뷰에서 실제 결과와 비교합니다.
